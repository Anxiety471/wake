Carry the silence in the message, and stop ringing when a ring is not needed (#343)

A wake is a message between bots, and the human should see that one arrived, not the
answer to it. That was a clause each bot had to carry in its own routine prompt, so
silence depended on the receiver's wording rather than on the message.

The flag now travels: `silent: true` in the payload (WAKE_SILENT=0 or --chatty sends
false), the same rule as one bracketed sentence at the end of `detail` for a receiver
that renders prose, and the flag on the ask record so the answer inherits the tone of
the question instead of each bot deciding again. The reply notice that wakes the asker
carries it too.

The one leg a flag cannot hide is the run a ring starts: a bot's answer to a run is
rendered in its chat, and the CLI cannot suppress that. `--reply --no-ring` therefore
sends nothing at all - the answer waits in the thread store for `wake --thread` or
`--inbox` - so no run starts and there is nothing to render. A live session inbox is
still pushed, because that is not a run.
